## 观察

- 100 行目标场景全部显著低于预算。
- `CodeFrame` 自身在 10000 行仍为毫秒级；`EditView` 的首次 render 随行数增长明显（10000 行 P95 96.66 ms）。
- 当前 `EditView` 默认折叠 3 个 hunk / 30 行；大会话仍需关注首次渲染与 resize。
- 缓存命中稳定为 0.00 ms（按宽度缓存）。

## 真实 Pi TUI：启用与禁用 EditView

同一台机器、相同 Pi/Node 版本，使用独立 `xterm-256color` PTY、42 行、初始宽度 120 列、Pi `fullscreen` 与 `dark` 主题。用 `--offline --no-approve -ne --no-mcp -ns -np -nc` 和临时 `PI_CODING_AGENT_DIR` 隔离用户配置，不发送模型提示，不执行会话里的工具。

- A 保留 Pi 的默认工具文本渲染；B 导入构建后的 pi-ui，为 `hashline` 注册 `renderShell: "self"` 和 `EditView`。两组回放等价的 Pi v3 JSONL：短会话是 1 条 100 行 diff，长会话是 1000 条不同路径的结果、每条 12 行 diff；每条含相同的 `content` 和 version 1 `details`。
- 冷启动从创建 PTY 子进程计时到首帧输出尺寸标记，随后用 `ps` 读取 RSS。短会话热渲染通过 `setToolsExpanded` 交替折叠/展开，主题切换通过 `setTheme` 交替 `light`/`dark`。长会话用 `switchSession` 来回切换 10 轮，每轮在长会话按 120→80→120→100→120 列缩放；用 PTY 输出里的当前会话 diff 和宽度标记确认渲染。冷启动、热渲染与长会话实验轮次交替 AB/BA。
- 从发出命令或调整 PTY 尺寸到读到新帧标记计时。包含宿主输入分发、渲染调度和 PTY 输出，不是单卡组件调用耗时，也不含图形终端的最终绘制。

### 长会话内存与 CPU 热点

常规 A/B 在各轮动作后读取 `process.memoryUsage()`，不触发 GC。另开一组相同的会话切换与缩放，通过 `HeapProfiler.collectGarbage` 采集存活堆，避免把尚未回收的分配当成泄漏。

| 检查点 | A RSS / heapUsed | B RSS / heapUsed | A GC 后 heapUsed | B GC 后 heapUsed |
|---|---:|---:|---:|---:|
| 第 1 轮 · 长会话 | 218.0 / 78.1 MiB | 452.5 / 106.7 MiB | 48.4 MiB | 52.6 MiB |
| 第 5 轮 · 长会话 | 335.9 / 117.9 MiB | 708.5 / 241.3 MiB | 50.1 MiB | 53.3 MiB |
| 第 10 轮 · 长会话 | 334.2 / 74.7 MiB | 709.8 / 145.8 MiB | 49.4 MiB | 52.7 MiB |
| 第 1 轮 · 切回短会话 | 216.6 / 53.2 MiB | 452.7 / 119.3 MiB | 36.3 MiB | 30.8 MiB |
| 第 10 轮 · 切回短会话 | 334.2 / 86.0 MiB | 709.8 / 157.3 MiB | 36.4 MiB | 30.7 MiB |

- B 的常规 RSS 在第 5–10 轮约为 709–710 MiB；GC 后存活堆在同一会话类型内没有持续增长。10 轮结果未显示逐轮增加的 JS 对象保留，不等于排除泄漏；高 RSS 和长会话缩放延迟仍是独立的性能风险。
- B 每轮长会话切入并缩放 4 次共产生 6000 次 `EditView.render`；切回短会话后是 2 次。单独采样一组长会话的 4 次缩放，排除空闲与 Inspector 调用后约 568 ms，其中约 371 ms（65%）落在由 pi-ui `displayWidth`、`hardTruncate`、`wrap` 调用的 Pi TUI 宽度与截断函数。优先减少长会话重排时的逐行 ANSI 宽度计算，而不是放宽预算。

### 行号栏宽度快路径

用相同 PTY 尺寸、会话 fixture 和缩放序列重新交替对照，两组均启用 EditView，只替换 pi-ui 构建产物。ASCII 代码、单列行号栏符号和 SGR 在一次扫描中计宽；遇到其他字符或转义格式仍由 Pi TUI 计算。不增加缓存。优化前后的窄列、中文、emoji、组合字符和 ANSI 样式共 52 组渲染输出逐字节一致。

| 场景 | 样本/组 | 优化前中位数 / P95 | 优化后中位数 / P95 |
|---|---:|---:|---:|
| 1000 条结果会话缩放 | 40 | 125.9 / 138.5 ms | 73.6 / 98.5 ms |
| 缩放至 80 列 | 10 | 137.7 / 147.0 ms | 95.8 / 106.0 ms |
| 切入 1000 条结果会话 | 10 | 142.2 / 182.0 ms | 94.7 / 126.0 ms |
| 第 10 轮长会话 RSS | 单次样本 | 638.7 MiB | 564.7 MiB |

与前一节的“默认文本 / EditView”不同，本节的两组均渲染面板。该轮长会话缩放 P95 同组对照下降 29%；RSS 是未强制 GC 的单轮观测，不作为内存上限或无泄漏证明。

### 120 轮会话切换压测

Pi 1.6.0、Node v25.9.0、macOS 26.7.2 arm64；复用上述 1000 条结果 fixture 和 120→80→120→100→120 列序列。A 为默认工具文本，B 为含行号栏快路径的 EditView。每组在同一进程中跑 120 轮（240 次会话切换、480 次缩放），轮次交替 AB/BA；两组共耗时 69.6 秒，之后停在短会话静置 45 秒。每次切换检查当前会话标记及真实 diff 输出，结束确认所有 fixture 文件字节未变。

| 场景 | 样本/组 | 默认渲染中位数 / P95 | EditView 中位数 / P95 |
|---|---:|---:|---:|
| 长会话缩放 | 480 | 21.3 / 25.1 ms | 72.6 / 105.0 ms |
| 切入长会话 | 120 | 37.6 / 54.9 ms | 86.4 / 105.4 ms |
| 切回短会话 | 120 | 17.3 / 19.5 ms | 20.6 / 23.1 ms |

在同一检查点先读取 `process.memoryUsage()`，再用 Inspector 强制 GC 并重采样。表中的 RSS 是采样值，不是系统记录的峰值。

| 检查点 | 默认渲染 RSS（GC 前 → 后） | EditView RSS（GC 前 → 后） | 默认渲染 / EditView 存活堆 |
|---|---:|---:|---:|
| 第 1 轮 · 长会话 | 204.8 → 134.1 MiB | 424.1 → 255.0 MiB | 38.0 / 50.0 MiB |
| 第 10 轮 · 长会话 | 332.5 → 140.6 MiB | 662.9 → 272.6 MiB | 38.3 / 49.9 MiB |
| 第 60 轮 · 长会话 | 407.1 → 144.8 MiB | 692.3 → 283.9 MiB | 38.7 / 51.2 MiB |
| 第 120 轮 · 长会话 | 409.1 → 147.3 MiB | 690.2 → 287.6 MiB | 39.8 / 51.6 MiB |
| 第 120 轮 · 切回短会话 | 151.8 → 134.8 MiB | 292.3 → 266.6 MiB | 27.0 / 30.6 MiB |
| 短会话静置 45 秒后 | 136.2 → 134.7 MiB | 268.0 → 266.5 MiB | 27.0 / 30.5 MiB |

EditView 第 60–120 轮 GC 前长会话 RSS 维持在约 690–692 MiB；从首轮到末轮，两组 GC 后长会话存活堆均增加不到 2 MiB。该轮未见 EditView 特有的线性存活堆增长，不能排除更慢的增长。

另起 10 轮对照，在切回短会话并强制 GC 后采集 `vmmap -summary`。`MALLOC_SMALL`（含 empty 区域）常驻页为默认渲染约 35.3 MiB、EditView 约 118.3 MiB；默认 malloc zone 的已分配字节为 14.0 / 19.2 MiB。该次采样中，当前物理 footprint 为 90.8 / 91.9 MiB，而峰值为 306.7 / 418.7 MiB。常驻页与存活分配量不能等同；现有证据定位到分配器区域，尚未定位具体分配栈。
